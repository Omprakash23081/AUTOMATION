# Cutroom Studio

Cutroom is a personal-use app that runs on your Windows computer; you do not need to deploy or host it. It accepts media uploads or public YouTube URLs and stores projects in local SQLite. For YouTube URLs, it downloads the source, retrieves available timestamped YouTube captions, asks an AI model to rank clip moments, and queues the requested top clips for automatic FFmpeg MP4 rendering with captions. Uploaded files continue to use audio transcription. Clip generation and MP4 rendering run in separate workers, so an export does not block a queued project; each lane processes one job at a time. Clips can be reviewed, edited, and previewed in their project workspace after rendering, and the app includes transcript search, SRT/VTT sidecars, workspace membership, and invite tokens. Switch between light and dark themes with the control in the top bar; your preference is saved in this browser. The clip editor supports adjustable captions (50% default size, Classic style, bottom position), fades, playback speed, color filters, slow zoom effects, and blurred-background fill for 9:16 exports. Portrait captions are constrained to a consistent-width lower safe area; position and alignment are centered automatically. Effects are rendered into the MP4 using FFmpeg.

An optional, constrained Netlify + Render deployment preview is documented in [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). It does not change the local workflow and is not a horizontally scalable or production-reviewed media service.

The browser application source is in `frontend/`, and the Flask application, Python helpers, and dependency manifest are in `backend/`. Root-level launchers and compatibility imports preserve the existing local commands and `server:app` WSGI entry point. Local runtime files remain in the repository-root `data/` folder.

## Start on Windows

Run `setup.bat` once to install dependencies, then `start.bat` whenever you want to use Cutroom. `start.bat` no longer installs packages on every launch. Or use PowerShell:

```powershell
python -m pip install -r backend/requirements.txt
python -m playwright install chromium
python start_local.py
```

Open `http://127.0.0.1:5000`, create a local account, and sign in. Use **AI settings** to add optional OpenAI, Google Gemini, and Groq API keys for the active workspace. With `CUTROOM_SECRET_ENCRYPTION_KEY` configured, credentials are encrypted before storage in SQLite; without it, local combined mode keeps keys in server memory for the current run. The local server reads `SESSION_SECRET` and `CUTROOM_SECRET_ENCRYPTION_KEY` from `.env` when present, including when `server.py` is launched directly. Restart the server after changing `.env`, then save the provider key again; a successful persistent save reports that it was encrypted and saved. Keys are never returned to the browser, and provider usage is billed by the corresponding provider. YouTube clip ranking tries OpenAI first, then Gemini, then Groq, and submits the same ranking prompt and transcript to ChatGPT in a signed-in Playwright browser session if those API providers fail or no API keys are configured. Groq defaults to `openai/gpt-oss-120b`; set `CUTROOM_GROQ_CLIP_MODEL` to select another supported Groq model. The native Windows app uses a persistent profile at `data\chatgpt_profile`; set `CUTROOM_CHATGPT_PROFILE_DIR` to use another profile. If that profile is already open, Playwright uses `data\chatgpt_fallback_profile`; sign in there once. If sign-in, MFA, or a human-verification page appears, complete it manually in the visible browser. In the native Windows app, the composer wait is ten minutes by default so there is time to complete verification; Docker runs headlessly and cannot accept manual interaction, so its default wait is 90 seconds and verification fails with a clear message. No anti-bot check is bypassed or solved automatically. Set `CUTROOM_CHATGPT_COMPOSER_TIMEOUT_SECONDS` to change either default. Keep the browser profile private because it contains your signed-in session. Set `CUTROOM_CHATGPT_BROWSER_CHANNEL` to an empty value to use Playwright's bundled Chromium instead of installed Chrome. Uploaded files still require OpenAI for audio transcription. Choose a video or paste a public YouTube URL, configure clip duration/count, platform, starting aspect ratio, transcription language, and custom instructions, then create the project. Open it from Recent projects and choose **Generate clips**. For YouTube sources, available captions are used instead of uploading source audio; selected clips render automatically. If YouTube does not provide accessible captions, processing reports that rather than silently switching to paid audio transcription. The project progress panel shows the current pipeline step, actual step percentage when available, and what the worker/provider is doing; it does not expose private model reasoning. If a queued job cannot see a recent worker heartbeat, the UI says the worker is unavailable and keeps the job safely queued until Cutroom/the Docker worker is restarted. Completed upload-transcription chunks are checkpointed and reused on retry; a chunk whose provider response was interrupted may still need to be sent again. Your projects and media remain under the local `data/` folder.

### YouTube dashboard setup

The **YouTube dashboard** connects Google accounts with OAuth so you can bring multiple channels into a workspace. Channels appear in a horizontal picker that can be sorted by subscribers, views, video count, or name; selecting one opens its details with the YouTube channel banner when available. It shows channel subscriber/view/video totals, recent uploads and their view counts, and can upload videos immediately or schedule them for later. Upload titles default to include `#shorts`; descriptions start with that title followed by the clip transcript when available. Recent videos can also be sent to the existing clip-project workflow. Channel analytics shown here are the channel's lifetime totals and per-video views, not YouTube Studio's full revenue or audience reports.

1. In Google Cloud Console, create or select a project, enable **YouTube Data API v3**, and configure the OAuth consent screen. Add your Google account as a test user if the consent screen is in testing mode.
2. Create an OAuth 2.0 **Web application** client. The YouTube dashboard displays the exact callback URL Cutroom is sending. Add that exact string as an **Authorized redirect URI** (not an Authorized JavaScript origin). For the default local address it is `http://127.0.0.1:5000/api/youtube/callback`. If the app is opened at a different hostname or port, register the URI displayed in the dashboard. You can pin it with `YOUTUBE_REDIRECT_URI` in `.env`; the value must match Google's registered redirect URI exactly, including scheme, hostname, port, and path. Alternatively, set `CUTROOM_PUBLIC_URL` to the app origin and register `<that-origin>/api/youtube/callback`.
3. Copy the client ID and secret into `.env` as `YOUTUBE_CLIENT_ID` and `YOUTUBE_CLIENT_SECRET`. Set a stable `CUTROOM_SECRET_ENCRYPTION_KEY` as described above; YouTube refresh tokens are encrypted in the local database and are not saved if encryption is unavailable. Restart Cutroom after changing `.env`.
4. Open **YouTube dashboard** and connect a Google account. Use **Connect YouTube account** again for each additional Google account/channel group you manage. Google may require OAuth verification for broader distribution; test-mode refresh tokens can expire under Google's testing-app policy.

Cutroom requests YouTube read access and video upload access. The browser never receives stored refresh tokens. Disconnecting an account removes its local channel data and asks Google to revoke its authorization. Uploads and scheduling use YouTube's API and are subject to Google's API quota and channel restrictions.

The standalone browser module can be smoke-tested before running a clip job:

```powershell
.\.venv\Scripts\python.exe backend\chatgpt_browser_automation.py --smoke-test --keep-open
```

This opens the persistent profile and checks that it navigates to `chatgpt.com` without sending a prompt; the browser remains open until you press Enter. Add `--wait-for-composer` to verify the signed-in ChatGPT composer too; the visible browser lets you sign in or complete a challenge manually while it waits. The pipeline uses this same module. On Windows it launches a visible browser by default; Docker Compose explicitly runs headlessly and cannot display a Windows desktop window. Progress reports browser launch, navigation, composer wait, and detected human-verification stages separately.

### Automation workflows

In the Cutroom app, open **Automation** and select **VIDEO EDIT AUTOMATION — sync Hindi dubbing**. Upload the Chinese video, Hindi audio, and timestamped `.txt` transcript in the same language as the narration using the three file fields, then start the workflow. Normalize/translate the transcript yourself before upload if needed. The synchronized MP4 appears in the completed job's downloadable files.

The **Automation** section adds the `YOUTUBE_VIDEO_AUTOMATION` workflows without replacing Cutroom’s clip-project flow. By default, it uses the copy inside the Cutroom project before checking for a sibling copy. Set `YOUTUBE_VIDEO_AUTOMATION_HOME` to explicitly select a different project directory. The integration uses the selected project’s `venv` or `.venv` Python when available; otherwise it uses the Python running Cutroom, which must have that project’s dependencies installed. Start Cutroom in local combined mode to run jobs.

Automation supports Kuaishou download/processing modes, YouTube batch download with English or Hindi captions, Gemini and ChatGPT transcription, local Whisper, English translation, Cartesia text-to-speech, and VIDEO EDIT AUTOMATION for synchronizing Hindi dubbing to a Chinese source video. Save both the Kuaishou backend URL and API key in workspace settings. The backend URL is used only to resolve each Kuaishou link to video/audio download links; the API key is Fernet-encrypted in SQLite and supplied to the downloader as `apikey` and `Authorization: Bearer` headers. The sibling downloader sends each Kuaishou link, including `v.kuaishou.com` short links, directly to the backend for resolution, then downloads the returned `videoUrl` and `audioUrl`. Backend resolution and failed-part downloads retry up to three times by default and log each attempt. Kuaishou filenames retain the `PART-<number>` marker and optionally add the video title suffix; the starting part number defaults to 61 and can be changed in the workflow form. These names are used consistently for videos, audio, and transcripts inside their respective subfolders. The YouTube batch workflow downloads authorized video URLs and matching captions, with English or Hindi selection, an optional local output folder, an output filename prefix, and a starting sequence number (default 1). You can enter an optional Cartesia voice ID in the YouTube workflow to choose a different character voice for that batch; leaving it blank uses the configured default. If a video has no 1080p format, the downloader selects the best available compatible format up to 1080p instead. Video and caption names share the chosen prefix and number. YouTube batch translates captions with the prompt in `youtube_automation\chatgpt\english.py`, then sends the English transcript to Cartesia and saves a WAV under `audio`; a Cartesia API key must be saved in Workspace Credentials. When a custom output folder is selected, its `videos`, `transcripts`, and `audio` outputs are included in Cutroom's downloadable output list. Modes 3 and 4 use the existing `YOUTUBE_VIDEO_AUTOMATION\playwright_profile` for Gemini and ChatGPT sign-in, matching the standalone workflow. If that Chrome profile is already open, the job uses a workspace-specific fallback profile under `data\automation`; sign in there once if prompted. Gemini starts only after media download succeeds, and no Gemini API key is needed. Mode 4 also runs the separate ChatGPT browser workflow on the Gemini transcript. Modes 1 and 2 only download media. Owners/admins can also save Cartesia credentials; `CUTROOM_SECRET_ENCRYPTION_KEY` is required to encrypt API keys, but not to save the Kuaishou URL by itself. Other browser workflows use separate workspace profiles under `data\automation`; the first run may open a visible browser so you can sign in manually. Folder scanning is read-only. Source transcripts/audio selected for processing are copied into a job-specific working folder, and generated files are retained under `data\automation\<workspace-id>\outputs` unless a Kuaishou or YouTube target folder is selected. A selected Kuaishou folder receives `videos`, `audio`, and `transcripts`; a YouTube folder receives `videos`, `transcripts`, and `audio`. Completed outputs can be downloaded from the job list. The automation jobs run locally in the Cutroom server process and are not supported in Docker or worker-only mode.

In the YouTube batch form, choose which steps to run: video download, plain transcript, English transcript, TTS audio, and timestamped transcript. All are checked by default to preserve the existing workflow. If a selected English transcript or TTS step needs a missing source transcript or English script, the required earlier transcript steps run automatically. The Cartesia key is required only when TTS is selected.

YouTube downloads are cached by video ID, so retrying a project can reuse a complete local source instead of downloading it again. Progress distinguishes checking the cache, resolving video details, transferring bytes, and validating the saved file; an idle notice reports elapsed time without declaring a still-running job failed. The project workspace continues polling while processing or clip rendering is active. In the clip editor, an unsaved edit is retried before closing; if saving still fails, the editor remains open so the changes are not silently discarded.

### Back up or restore your local library

Stop Cutroom, then run `python backup.py`. It creates a timestamped ZIP in `backups/` containing the configured data folder (by default `data/`). Set `CUTROOM_BACKUP_DIR` to choose another backup location. Keep the archive somewhere separate from this computer for protection against drive failure. To restore, stop Cutroom, extract the archive into the project folder so its `data/` directory replaces the current one, then start the app. Backups do not contain `.env` or environment variables; preserve `CUTROOM_SECRET_ENCRYPTION_KEY` separately if you use it to encrypt a saved provider key.

### Start with Docker Compose

Docker Compose runs the Flask web/API and a separate media-worker process as non-root containers. The media worker runs independent generation and export lanes, one job at a time per lane, so a long render does not block clip generation. They share the SQLite-backed queue and keep the database, uploads, thumbnails and exports in a named persistent volume. Workspace API keys are Fernet-encrypted in SQLite; the worker requests only the job workspace key over the private Compose bridge using the shared session secret. Chromium is installed for the browser fallback, which runs headlessly with a separate profile in the persistent data volume. The standard Compose setup has no interactive desktop, so it cannot complete ChatGPT sign-in, MFA, or human verification in that browser; a headless-profile timeout now fails with guidance rather than waiting ten minutes. For browser fallback with manual sign-in or verification, use the native Windows server (`python start_local.py`) so Playwright can open a visible browser. This launcher reads the encryption and session secrets from `.env`. The native server uses the local `data\` folder, which is separate from Compose's named volume; migrate or back up the Docker library before switching if you need those existing projects and files. Otherwise, keep Docker running and use configured API providers. This is a local split-process deployment; it does not add PostgreSQL, Redis, or object storage and is not a public SaaS deployment. The published port binds to `127.0.0.1` only.

```powershell
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
# Put the first value in SESSION_SECRET and the Fernet value in CUTROOM_SECRET_ENCRYPTION_KEY in .env.
docker compose up --build -d
docker compose ps
```

Open `http://127.0.0.1:5000`. `docker compose logs -f api worker` shows service logs; `docker compose down` stops the app while preserving data. `docker compose down -v` permanently deletes the named database/media volume. If port 5000 is busy, set `PORT=5001` in `.env` before starting. Keep `.env` private. The API accepts requests only through the configured local Docker subnet and only for localhost hostnames.

Supported uploads: MP4, MOV, WebM, M4V, MP3, M4A, and WAV; maximum 4 GB and 3 hours. Browser uploads use resumable 8 MiB chunks with acknowledged offsets, progress, retry, cancellation, and same-browser resume when the same file is selected again. Abandoned partial sessions expire after 24 hours; completed source files are stored on the local data volume. After upload, the server probes duration, frame rate, dimensions and audio/video presence, and generates a private source thumbnail when video frames are available. The server binds to loopback only, keeps media under `data/`, and serves only the app's public browser assets. Project metadata and clip drafts are stored in `data/cutroom.sqlite3`. This local upload protocol is not S3-compatible multipart upload and does not provide cross-device resume or production storage quotas.

## Account and team controls

The workspace dialog lists members for owners and admins. Owners can transfer ownership to an existing teammate (the previous owner becomes an admin) or remove workspace members. Admins can remove editors and viewers but cannot remove another admin or transfer ownership. Account deletion requires the current password and typed confirmation; it deletes sole-member workspaces and their app-managed media, preserves shared workspace content, and removes the account's memberships. A user who still owns a shared workspace must transfer ownership before deletion.

## What is connected

- SQLite project, clip, and processing-job persistence with visible status and a three-attempt per-job retry limit.
- Docker Compose local runtime with non-root, read-only API and worker containers, a persistent named data volume, health check, bounded logs, and loopback-only port publishing.
- Private local uploads and public YouTube URL ingestion through `yt-dlp` (subject to platform access and source rights).
- YouTube downloads use stable video-ID filenames and reuse validated completed files on retry; fetched captions are saved before clip ranking so a ranking retry does not fetch them again.
- When YouTube explicitly disables captions, processing stops with a clear, non-retryable error. Cutroom does not automatically send that video's audio for paid transcription.
- FFmpeg/OpenCV media probing, source thumbnails and metadata (dimensions, frame rate, audio/video presence), audio extraction/chunking, timestamped transcription, and MP4 clip rendering with original audio.
- Timestamped captions from available YouTube caption tracks for YouTube URL projects; OpenAI transcription (`whisper-1`) remains the path for uploaded files. Transcript-based moment selection uses OpenAI `gpt-4o-mini`, then the configured Gemini `gemini-3.8-flash` key, then Groq (default model `openai/gpt-oss-120b`), and finally the signed-in ChatGPT Playwright browser if all configured API providers fail.
- YouTube URL projects automatically queue MP4 rendering for the selected top K, with ranked results and render progress/downloads shown in the project view. Ranking uses transcript evidence; it does not yet analyze video frames for visual interest or perform subject tracking.
- Editable title and cut points, zoomable source timeline with draggable trim handles, undo/redo and saved edit history; render and preview the edited MP4 in the editor before choosing to download it, with trimmed SRT captions available separately.
- Workspace Brand Kit defaults for caption font, color, box color and preset, captured in saved edits and applied during export.
- Workspace Storage library for source videos and validated logos/images/audio. Source video deletion is permanent and also removes its linked projects, clips, edit history, captions, thumbnails, exports, and transcription checkpoints; deletion is blocked while uploads, generation, or exports are active and when another workspace shares the source. Source videos and completed exports otherwise remain until explicitly deleted. Abandoned upload sessions and crash-left temporary media become eligible for cleanup after 24 hours and are swept at worker startup (expired upload sessions are also swept when another upload starts); completed transcription retry checkpoints are removed after successful processing. Select a logo and looping background music, then add up to eight more workspace audio assets as positioned timeline tracks with independent volume and fades; FFmpeg mixes the saved track positions into the rendered MP4. The browser preview still plays the source rather than a live composite mix.
- Clip exports let you choose 480p, 720p or 1080p, 24/25/30/50/60 fps, and a 2.5–16 Mbps bitrate preset alongside portrait, square or landscape framing.
- Clip exports run as persistent background jobs with FFmpeg progress, cancel/retry actions, workspace-private result downloads, and editor polling that resumes if reopened.
- A local asset endpoint provides workspace-scoped access. Files stay on the configured local data volume; this is not cloud object storage.

## Boundaries before public launch

This is a local development build, not a hosted production service. It supports local email/password accounts, workspace memberships/roles, invitation tokens, scoped projects, session-bound CSRF tokens, same-origin checks, expiring one-time email verification and password-reset tokens, SQLite-backed fixed-window throttles on account endpoints, and account deletion. Deletion requires the current password and typed confirmation; it removes sole-member workspaces and their stored media, while preserving shared workspace data and removing the departing membership. Owners must transfer ownership before deleting an account with teammates. For local use, `CUTROOM_EMAIL_MODE=disabled` is the default and registrations verify immediately. To deliver real verification/recovery messages, set `CUTROOM_EMAIL_MODE=smtp` and configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, optional SMTP credentials, and TLS settings in the server environment; use `CUTROOM_PUBLIC_URL` for the externally reachable HTTPS origin when behind a proxy. SMTP delivery has not been verified against a real provider. This mode requires verified accounts to sign in and password reset invalidates existing sessions. The account throttles apply per client IP and, where relevant, email, but SQLite makes them single-host controls; production multi-host rate limiting needs a shared store such as Redis and trusted proxy configuration. Set `SESSION_COOKIE_SECURE=true` when serving over HTTPS; it remains false for local HTTP. AI keys are workspace-scoped and Fernet-encrypted at rest when `CUTROOM_SECRET_ENCRYPTION_KEY` is configured; local combined mode otherwise keeps keys only in memory. The native server binds to loopback; the optional Compose runtime publishes only to host loopback. Media and SQLite are local. Processing jobs are persisted and recovered from interrupted local workers, with cancel requests and a user-triggered retry limit of three attempts; in-flight AI calls finish before cancellation is observed. Compose separates API and media-worker processes but both use a single-host SQLite queue and shared local volume, not Redis/BullMQ. Only one worker should run because processing leases/heartbeats are not implemented. Before public hosting, add distributed durable workers, object storage, quotas, malware scanning, monitored retention/deletion, production-grade secrets/key rotation, observability, migrations, backup/restore, and full security/E2E testing. YouTube access and permitted use depend on source availability and platform terms; process only content you are authorized to use.

## Additional working modules

The All clips library and Project Workspace let you permanently delete unwanted clips; each clip's saved edit history and rendered files are removed with it.

The app also supports transcript keyword search, timestamp-based clip drafts, persisted transcript corrections and recoverable segment removal/restoration; searchable project and All clips libraries with filters and pagination; a saved Kanban Ideas board; and a content-planning calendar. Clip edits autosave as immutable EDL versions with up to 20 non-overlapping source segments in output order. The timeline supports splitting at the playhead, removing, reordering and trimming the selected segment, undo/redo and export-time concatenation; captions, source audio and extra audio follow the edited output timeline. Manual horizontal and vertical crop focus is saved in the EDL; the editor preview and FFmpeg output use the same crop position. Caption controls include font, size, colors, outline, alignment, vertical safe-area position, and optional word-by-word highlighting. Word highlighting uses timestamped ASS karaoke captions when saved word timings exist; text corrections clear timing for that segment, and export reports when it falls back to static captions. OpenAI notes that word timestamps add transcription latency: [transcription API reference](https://platform.openai.com/docs/api-reference/audio/createTranscription). The editor still lacks automatic subject tracking, B-roll/video overlay lanes, transitions, frame-accurate preview and a live composite preview; image overlays remain a single logo layer. The calendar stores planned posts only; it does not publish or claim successful social posting. Clip export supports portrait, square and landscape formats, burned-in caption presets, plus SRT and VTT sidecars.

## Verification

Run the local integration suite with:

    python -m unittest discover -s tests -v

It creates synthetic video/audio and image fixtures and checks upload, SQLite project operations, transcript search/draft creation, FFmpeg crop/caption/logo-overlay exports and sidecars, workspace isolation, and persistent job recovery/retry metadata. It does not call an AI provider or prove YouTube ingestion; those still need an authorized API key and source test.
